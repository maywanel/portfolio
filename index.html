Webserv

An HTTP/1.1 server, built from the socket up. A closer look at what really happens between a request and a response.

Request parsing. Nonblocking connections.
Every layer, understood and implemented.

  • C++98
  • POSIX sockets
  • epoll
  • HTTP/1.1
Explore repository for Webserv

The challenge

Handle multiple clients without blocking the server, while turning raw socket data into valid HTTP requests and responses.

The implementation

Nonblocking sockets and epoll manage connections. Request parsing, routing, CGI execution, and file uploads form the application layer.

What I learned

Protocol details matter. Following a request through each layer makes connection handling and server behavior much easier to reason about.

Inception

A multi-service environment with clear boundaries. Separate containers, persistent data, and one controlled entry point.

  • Docker
  • Compose
  • Nginx
  • MariaDB
  • Redis
Explore repository for Inception

The challenge

Give each service its own responsibility while keeping networking, storage, and startup behavior understandable.

The implementation

Docker Compose connects the services through an organized network. Nginx handles TLS termination; volumes preserve data across container restarts.

What I learned

Infrastructure is part of the application. Service boundaries, persistence, and restart behavior need the same attention as application logic.

The challenge

The implementation

What I learned

Authentication, authorization, and data access are distinct concerns. Keeping those responsibilities clear makes a backend easier to extend.
